# repo-fit-check

쓰려는 GitHub 저장소가 내 프로젝트에 맞는지 알아보는 Claude 스킬입니다. 목적과 단계, 제약(라이선스나 언어 같은 것)을 말하면 후보 저장소를 찾아서 관련도 순으로 정리해 줍니다.

지금 되는 것은 후보를 찾는 데까지입니다. 이슈와 PR 상태를 확인하거나 README가 말하는 기능이 코드에 실제로 있는지 대조하는 검증, 그리고 "맞는 점 / 안 맞는 점 / 확인 못한 점" 리포트는 아직 만들지 않았습니다. 그래서 출력은 후보 목록이고, 어떤 저장소도 적합하다고 판정하지 않습니다.

## 만든 이유

별표를 눌러 둔 저장소가 800개를 넘습니다. 새 프로젝트를 시작하면 그중 무엇이 쓸 만한지 기억나지 않아서 다시 찾으려면 같은 검색을 처음부터 하게 됩니다.

저장소를 골라 주는 도구는 이미 있어서 두 가지를 먼저 직접 돌려 봤습니다. claude-github-scout는 결과를 스타 수 순으로 내놓았습니다. 좁은 주제로 찾으면 스타만 많고 상관없는 저장소가 위로 올라왔습니다. 문장으로 검색하면 0건이 자주 나왔습니다. repohealth는 문서, 테스트, CI 같은 위생 상태를 점수로 매기는 도구인데, 코드가 아닌 스킬 저장소는 테스트가 없다는 이유로 낮게 나왔습니다. 스타가 15만 개인 agency-agents가 49점(D)이었습니다. 두 도구 모두 내 목적에 맞는지는 알려 주지 않았습니다. 이 스킬은 그 빈칸을 채우려고 시작했습니다. 첫 단계인 후보 탐색을 먼저 만들었습니다.

## 설치

`gh` CLI에 로그인되어 있고 Python 3가 있으면 됩니다. GitHub MCP는 필요 없습니다. 스킬 폴더에 그대로 받으면 설치가 끝납니다.

```bash
git clone https://github.com/junthropic/Repo-Fit-Check.git ~/.claude/skills/repo-fit-check
```

새 세션에서 `/repo-fit-check`를 부르거나, "스타 목록에서 한국 노동법 도구로 쓸 만한 저장소 골라 줘"처럼 말하면 됩니다.

## 쓰는 법

스킬은 먼저 목적에서 영어 검색어를 뽑습니다. 검색어는 쉼표로 나눈 개념 묶음입니다. 한 묶음 안에서는 `|`로 동의어를 적습니다. 스크립트를 직접 실행하면 이렇게 됩니다.

```bash
python ~/.claude/skills/repo-fit-check/scripts/discover.py \
  --terms "korea|korean, labor|employment, law|statute|compliance" \
  --license MIT,Apache-2.0,BSD-3-Clause --avoid AGPL
```

내 스타 목록을 먼저 같은 기준으로 채점한 뒤 GitHub 검색 결과를 붙입니다. `--license permissive`는 MIT, Apache-2.0, BSD, ISC 등 허용형 13종을 한 번에 지정합니다. 목록을 줄 때는 목록에 없는 라이선스와 GitHub이 식별하지 못한 라이선스 모두 점수를 깎습니다. 한국어 목적을 `--purpose "한국 노동법 점검"`처럼 줄 수도 있습니다. 이때는 `references/ko_glossary.json`에 있는 한국어를 영어로 바꿉니다. 영어 문장에서는 `am`, `can`, `the` 같은 군더더기를 걷어내고, 걷어낸 말 중 검색어였을 수 있는 것(`help`, `looking` 등)은 결과 맨 앞에 알려 줍니다. 용어집이 모르는 한국어는 결과 맨 앞에 "알아듣지 못해 뺐다"고 적습니다. 알아들은 단어가 하나도 없을 때만 오류로 멈춥니다. 검색어가 6개를 넘으면 뺀 것도 알려 줍니다.

2026년 10월 12일에 위 검색어로 돌린 결과의 일부입니다.

| 저장소 | 스타 | 라이선스 | 관련도 |
|---|---:|---|---:|
| kimlawtech/korean-contracts | 62 | 표기 없음 | 1.00 |
| taxwoong/labor-mcp | 2 | MIT | 0.93 |
| kentaroajisaka/labor-law-mcp | 63 | MIT | 0.68 |
| chrisryugj/korean-law-mcp | 2,681 | MIT | 0.58 |

스타가 2,681개인 저장소보다 62개인 저장소가 위에 있습니다. 순위가 스타 수가 아니라 관련도로 정해지기 때문입니다.

## 순위를 매기는 방식

점수는 관련도 70%, 최근 활동 15%, 스타 10%, 라이선스 5%로 합칩니다. 스타는 로그로 줄이고 상한을 두어서 10만 개와 100만 개를 같게 취급합니다. 관련도는 저장소 이름, 토픽, 설명에서 검색어가 얼마나 잡히는지로 계산합니다. 후보 안에서 드문 단어일수록 더 크게 반영합니다. "compliance"는 어디에나 있지만 "korea"는 드물기 때문입니다. 저장소 어디에도 없는 단어는 가중치를 0으로 두어 점수에서 뺍니다. 그 사실은 결과에 적습니다.

스타가 500개보다 적으면서 관련도가 높은 저장소는 큰 저장소에 밀리지 않도록 표를 따로 보여 줍니다. 후보가 모자라면 검색을 점점 느슨하게 바꿔서 다시 찾습니다. 순서는 단어 하나 빼기, 토픽, 단어 쌍, 동의어이고 최대 16번까지 반복합니다. 어떤 검색을 했고 몇 건이 나왔는지는 결과 끝에 그대로 출력됩니다. `--avoid`에 적은 라이선스는 결과에서 빼고 제외 사유를 남깁니다.

## 이미 쓰는 도구 확인하기

`scripts/scan_env.py`는 지금 쓰는 환경을 읽어서 이미 있는 기능과 비어 있는 기능을 나눕니다. 사용자 스킬뿐 아니라 플러그인 폴더의 스킬과 에이전트, MCP 서버 이름, `~/.claude.json`, Codex 설정까지 봅니다. 설정 파일은 `~/.claude.json` 전체를 메모리로 읽지만 서버 이름만 골라 냅니다. 토큰이나 환경 변수 값은 결과에 싣지 않습니다. 이 동작은 테스트로 고정해 두었습니다.

결과 파일에는 홈 경로와 스킬 설명이 들어 있어서 `~/.cache/repo-fit-check/` 아래에 소유자만 읽도록(0600) 저장합니다. Windows에서는 이 권한 설정이 적용되지 않습니다.

디스크에 없는 정보는 볼 수 없습니다. claude.ai 커넥터의 현재 연결 상태가 그런 경우여서, 세션에서 보이는 이름을 `--live` 파일에 한 줄씩 적어 넘기면 함께 계산합니다. 이름이 세 곳 미만에서만 일치한 항목은 `weak`로 표시합니다. 키워드 매칭이라 "있다"고 단정하기 어렵기 때문입니다.

## 한계

검색 품질은 검색어에 크게 좌우됩니다. `fit`이나 `tool`처럼 뜻이 넓은 단어를 넣으면 관련 없는 저장소가 많이 섞입니다. 설명과 토픽이 한국어로만 적힌 저장소는 영어 검색어에 걸리지 않을 수 있습니다. 환경 스캔의 공백 판정도 키워드에 의존해서, 스킬이 수백 개 있는 환경에서는 거의 모든 분야가 채워진 것으로 나옵니다. 그리고 앞에서 적은 대로 검증과 판정 단계는 아직 없어서, 후보로 올라온 저장소를 쓸지는 직접 열어 보고 정해야 합니다.
